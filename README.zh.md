# dsh-workspace-todos

给 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 用的跨工作区待办本：卡片式界面供人编辑，同时通过工具让智能体编辑，两者读写同一个 JSON 文件。

[English](README.md)

## 它提供什么

- **一份清单，所有工作区共用。** 每条待办带着所属工作区目录，页面按工作区列表的顺序分组。不存在“每个会话各一份”的情况：在一个会话里加的待办，别的会话也看得到。
- **卡片 + 基础 Markdown。** 段落与换行、`#`–`######` 标题、有序/无序列表、引用、围栏代码、行内代码、**粗体**、*斜体*、~~删除线~~、`http(s)`/`mailto` 链接。全部解析成 React 节点，不注入 HTML。
- **智能体读写同一份。** 任意会话都能调用 `workspace_todos` 工具：`list`、`add`、`update`（改文字或勾选）、`remove`。智能体改完后，打开着的页面几秒内自动刷新。
- **三个入口、一份数据。** 左侧栏入口打开整页；右侧边栏标签页只显示当前会话所属工作区；也可以直接手改磁盘上的 JSON。

## 安装

要求：支持 bundle 的 DeepSeek Harness。本文档对应 Desktop 应用（DSH `0.2.2-rc.5`，profile 为 `desktop`）。

克隆仓库后，把这个目录作为 bundle 安装：

- **在应用里**：**插件** → **添加插件** → 选择该目录；或
- **在会话里**：让智能体安装这个本地目录（`plugin_manager` 的 `install_bundle`，参数为目录绝对路径）。

激活后：

- **插件**页会列出 *跨工作区待办本*，带自己的图标；
- 左侧栏多出待办清单入口；
- 右侧边栏的“+”里能在指引页看到它；
- 每个会话的智能体都能调用 `workspace_todos`。

无需构建、无依赖：`client.js` 直接以 Web 模块加载器要求的形态编写，`index.js` 只 import `node:` 内置模块。

## 使用

**左侧栏 → 跨工作区待办本**：中间列显示完整清单，按工作区分组，顶部是录入卡片（选工作区，`Ctrl/Cmd+Enter` 添加），勾选框标记完成，铅笔改 Markdown 原文，垃圾桶删除，“返回对话”回到会话。

**右侧边栏 → + → 跨工作区待办本**：面板只显示当前会话所属工作区的卡片，新增也归到该工作区。右栏状态按会话保存，切换到别的会话会显示那个会话的工作区。

## 智能体工具

| action | 参数 | 作用 |
|---|---|---|
| `list` | `workspace`（可选：路径、路径片段或工作区名） | 返回全部或匹配的卡片 |
| `add` | `text`、`workspace`（绝对目录）、`label`（可选，默认取目录名） | 追加一条未完成卡片 |
| `update` | `id`，以及 `text`、`done`、`workspace`、`label` 中的任意项 | 修改该卡片 |
| `remove` | `id` | 删除该卡片 |

每个操作都返回完整清单，模型始终看到当前状态；`id` 来自上一次结果。

## 数据存放

清单是一个文件：

```
<DSH_HOME>/workspace-todos.json
```

```json
{
  "version": 1,
  "items": [
    {
      "id": "…uuid…",
      "workspacePath": "D:\\work\\alpha",
      "workspaceLabel": "alpha",
      "text": "写接口文档",
      "done": false,
      "createdAt": "2026-11-25T08:00:00.000Z"
    }
  ]
}
```

- 文件不存在即空清单，首次写入时创建；不是本格式或版本不符时报错，不会静默替换。
- 写入先写临时文件再一次 `rename`，操作串行化，两个写入方不会把读写交错。
- 每次操作都先重读文件，所以手工编辑会在下一次页面轮询和下一次工具调用时生效。
- 页面通过 Connection 共享通道上的精确 Fetch 路由 `/api/workspace-todos` 访问 Host，在浏览器鉴权之后。

## 支持的 Markdown

支持：段落与换行、`#`–`######` 标题、`-`/`*`/`+` 与 `1.` 列表、`>` 引用、围栏代码、行内代码、粗体、斜体、删除线，以及 `http(s):`、`mailto:` 链接。其余（表格、图片、嵌套列表、引用式链接、任务列表勾选框、HTML、转义）按纯文本显示。

## 限制

- 一份文件即一份清单：共用同一个 `DSH_HOME` 的两个 DSH 进程写同一文件，没有跨进程锁（按操作后者覆盖）。
- 卡片只有 Markdown 文本、完成状态和所属工作区：没有截止日期、优先级、标签、附件和排序。
- 界面是 3 秒轮询而非推送，智能体改动最多滞后这个间隔。
- 工作区被删除后，分组保留添加时的名字，排在现存工作区之后。
- 基于 DSH `0.2.2-rc.5` 的 bundle 接口编写，其他版本可能需要小幅调整。

## 仓库结构

```
.
├── package.json        bundle 清单（dsh.bundle.patch、dsh.client）
├── cordis.patch.yml    插入唯一的 Host 行
├── index.js            Host 半：文件存储、Fetch 路由、智能体工具
├── client.js           浏览器半：左栏入口、中间页、右侧边栏标签页
├── locale/en.json      插件页标题与描述（英文）
├── locale/zh.json      插件页标题与描述（中文）
└── icon.svg            插件图标
```
