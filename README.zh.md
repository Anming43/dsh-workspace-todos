# dsh-workspace-todos

给 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 用的跨工作区待办本：卡片式界面供人编辑，同时通过工具让智能体编辑，两者读写同一个 JSON 文件。

[English](README.md)

## 它提供什么

- **一份清单，所有工作区共用。** 每条待办带着所属工作区目录，页面把**未完成**卡片按工作区列表的顺序分组。不存在“每个会话各一份”的情况：在一个会话里加的待办，别的会话也看得到。
- **完成的收进下方区域。** 勾选后卡片离开所在分组，收进页面底部的“已完成”区域，默认折叠；右侧边栏面板同样只在底部收该工作区的已完成卡片。区域标题显示数量，点一下展开或收起。
- **最近改过的排最前。** 每条卡片记录最后修改时间（`updatedAt`，卡片上显示为 `2026-11-25 17:40`），两个界面都按修改时间倒序排列，刚动过的卡片自动升到最前。
- **每张卡片都有自动生成的待办 ID。** 徽标是存储 UUID 的前 8 位十六进制，卡片存续期间不变、不需要计数器也不会重号；人对人引用用徽标，智能体在工具结果里拿到完整 id。
- **编辑用大弹窗。** 铅笔打开一个覆盖窗口的大弹窗：拖右下角调整大小，最大化按钮铺满屏幕，Esc 或“关闭”放弃草稿，Ctrl/Cmd+Enter 保存。弹窗是浏览器顶层（top layer）里的原生 `<dialog>`，打开时页面其余部分不可交互。
- **每张卡片两个按钮。**「执行待办」把卡片作为一条普通用户消息发进会话，要求智能体去做；「解释待办」发同一张卡片，但要它先解释——要做什么、为什么、涉及哪些文件或步骤、哪里不清楚——并且不要改动。两条消息都带着 ID、工作区、状态和修改时间，智能体据此找回卡片并用 `workspace_todos` 关闭。
- **卡片 + 基础 Markdown。** 段落与换行、`#`–`######` 标题、有序/无序列表、引用、围栏代码、行内代码、**粗体**、*斜体*、~~删除线~~、`http(s)`/`mailto` 链接。全部解析成 React 节点，不注入 HTML。
- **智能体读写同一份。** 任意会话都能调用 `workspace_todos` 工具：`list`、`add`、`update`（改文字或勾选）、`remove`。智能体改完后，打开着的页面几秒内自动刷新。
- **三个入口、一份数据。** 左侧栏入口打开整页；右侧边栏标签页只显示当前会话所属工作区；也可以直接手改磁盘上的 JSON。

## 安装

要求：支持 bundle 的 DeepSeek Harness。本文档对应 Desktop 应用（DSH `0.2.2-rc.5`，profile 为 `desktop`）。

克隆仓库后，把这个目录作为 bundle 安装：

- **在应用里**：**插件** → **添加插件** → 选择该目录；或
- **在会话里**：让智能体安装这个本地目录（`plugin_manager` 的 `install_bundle`，参数为目录绝对路径）。

激活后：

- **插件**页会列出 *跨工作区待办本*，带自己的图标；
- 左侧栏多出待办清单入口；
- 右侧边栏的“+”里能在指引页看到它；
- 每个会话的智能体都能调用 `workspace_todos`。

无需构建、无依赖：`client.js` 直接以 Web 模块加载器要求的形态编写，`index.js` 只 import `node:` 内置模块。

## 使用

**左侧栏 → 跨工作区待办本**：中间列显示完整清单，未完成卡片按工作区分组，顶部是录入卡片（选工作区，`Ctrl/Cmd+Enter` 添加），勾选框标记完成，铅笔打开 Markdown 编辑弹窗（可拖拽调整大小、可最大化），垃圾桶删除，“返回对话”回到会话。勾选后卡片收进底部“已完成”区域（默认折叠），在那里取消勾选会把它放回未完成列表。卡片操作区的播放按钮是「执行待办」，问号按钮是「解释待办」，都发送到**最近一次显示的会话**（整页本身没有所属会话）；右侧边栏面板则发到它所属的那个会话。发送成功后按钮变成对勾几秒，失败会显示在页面的错误行里。

**右侧边栏 → + → 跨工作区待办本**：面板只显示当前会话所属工作区的卡片，新增也归到该工作区。右栏状态按会话保存，切换到别的会话会显示那个会话的工作区。

## 智能体工具

| action | 参数 | 作用 |
|---|---|---|
| `list` | `workspace`（可选：路径、路径片段或工作区名） | 返回全部或匹配的卡片 |
| `add` | `text`、`workspace`（绝对目录）、`label`（可选，默认取目录名） | 追加一条未完成卡片 |
| `update` | `id`，以及 `text`、`done`、`workspace`、`label` 中的任意项 | 修改该卡片 |
| `remove` | `id` | 删除该卡片 |

每个操作都返回完整清单，模型始终看到当前状态；结果按修改时间倒序，并带上每条卡片的 `updatedAt`。`id` 来自上一次结果。

## 数据存放

清单是一个文件：

```
<DSH_HOME>/workspace-todos.json
```

```json
{
  "version": 1,
  "items": [
    {
      "id": "…uuid…",
      "workspacePath": "D:\\work\\alpha",
      "workspaceLabel": "alpha",
      "text": "写接口文档",
      "done": false,
      "createdAt": "2026-11-25T08:00:00.000Z",
      "updatedAt": "2026-11-25T09:40:00.000Z"
    }
  ]
}
```

- 文件不存在即空清单，首次写入时创建；不是本格式或版本不符时报错，不会静默替换。
- 写入先写临时文件再一次 `rename`，操作串行化，两个写入方不会把读写交错。
- 每次操作都先重读文件，所以手工编辑会在下一次页面轮询和下一次工具调用时生效。
- 每次改动都会重写 `updatedAt`。1.0.0 写下的记录只有 `createdAt`，在下次写入前用它代替修改时间，之后两者都会落盘。
- 文件里保持记录添加的先后顺序；`list` 和两个界面都按 `updatedAt` 排序，不信任文件顺序。
- `#` 徽标由 `id` 推导，不落盘：没有新增字段，徽标上线前写入的旧记录也照样有。
- 页面通过 Connection 共享通道上的精确 Fetch 路由 `/api/workspace-todos` 访问 Host，在浏览器鉴权之后。

## 支持的 Markdown

支持：段落与换行、`#`–`######` 标题、`-`/`*`/`+` 与 `1.` 列表、`>` 引用、围栏代码、行内代码、粗体、斜体、删除线，以及 `http(s):`、`mailto:` 链接。其余（表格、图片、嵌套列表、引用式链接、任务列表勾选框、HTML、转义）按纯文本显示。

## 限制

- 一份文件即一份清单：共用同一个 `DSH_HOME` 的两个 DSH 进程写同一文件，没有跨进程锁（按操作后者覆盖）。
- 卡片只有 Markdown 文本、完成状态和所属工作区：没有截止日期、优先级、标签、附件和手动排序——顺序固定为最后修改时间。
- “已完成”区域每次进入界面都是折叠的，展开状态不跨访问保存。
- 整页发送的目标是“最近一次显示在屏幕上的会话”；启动后一个会话都没开过时两个按钮都是禁用的，右侧边栏面板则总有它自己的会话。
- 发送出去的是一条普通用户消息：「执行待办」在会话空闲时直接起一轮，除了删掉这条消息没有撤销；「解释待办」要求智能体保持卡片未完成。
- 界面是 3 秒轮询而非推送，智能体改动最多滞后这个间隔。
- 工作区被删除后，分组保留添加时的名字，排在现存工作区之后。
- 基于 DSH `0.2.2-rc.5` 的 bundle 接口编写，其他版本可能需要小幅调整。

## 验证情况

1.3.0 做过：两个入口的 `node --check`；Host 半测试（本次未改 Host）；浏览器半的加载与注册冒烟；以及对编辑器的静态复核——原生 `<dialog>` + `showModal()`、`cancel` 事件映射到取消、textarea 的 Ctrl/Cmd+Enter、两个界面都用同一份编辑状态挂载弹窗。

1.2.0 做过：两个入口的 `node --check`；Host 半在临时 `DSH_HOME` 上的测试（本次未改 Host，仍覆盖存储、时间戳、排序与 Fetch 信封）；浏览器半的加载与注册冒烟，补齐了 `sessions`、`uiSession` 两个依赖，验证三个 slot 注册。

1.1.0 做过：Host 半在临时 `DSH_HOME` 上的测试——增删改、工作区筛选、各类拒绝、版本不符与损坏记录、新增和每次修改都写 `updatedAt`、按修改时间倒序、1.0.0 记录在下次写入时补齐字段、Fetch 路由的 client-request 信封；以及浏览器半的加载与注册冒烟（模块 id、依赖注入、三个 slot 注册），不做渲染。

1.0.0 另外做过：用已安装的 `@deepseek-ai/dsh-tools` 校验参数与输出 schema；Markdown 解析用例；用最小 React 替身渲染两个界面；并在 Desktop 应用里真机验证过激活、工具往返、鉴权路由和中间页。

**未验证**：底部“已完成”折叠区、时间戳、ID 徽标、两个发送按钮和编辑弹窗都没有在运行中的应用里看过——本机拿不到浏览器控制。两条发送路径走的都是输入框同一条 `Session.prompt` 调用和“最近在屏会话”来源，但真实发送还没有实际点过；弹窗的拖拽缩放手柄和最大化状态也还没实际观察。
