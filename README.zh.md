# dsh-workspace-todos

给 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 用的跨工作区待办本：智能体通过工具维护待办，人在卡片板上阅读——卡片看标题和摘要，点开弹窗看完整详情。

[English](README.md)

## 它提供什么

- **一份清单，所有工作区共用。** 每条待办带着所属工作区目录，页面把**未完成**卡片按工作区列表的顺序分组。不存在“每个会话各一份”的情况：在一个会话里加的待办，别的会话也看得到。
- **标题、摘要、详情三段。** 每条待办由一行标题、一小段纯文本摘要和 Markdown 详情组成；卡片显示前两段，详情在点开卡片后的弹窗里。
- **页面只读。** 没有新增、编辑、勾选、删除按钮——这些改动全部由智能体通过 `workspace_todos` 工具完成，页面只反映智能体写下的内容。点卡片打开只读的详情弹窗：可拖右下角调整大小、可最大化、Esc 关闭。
- **完成的收进下方区域。** 勾选（由智能体完成）后卡片离开所在分组，收进页面底部的“已完成”区域，默认折叠；右侧边栏面板同样只在底部收该工作区的已完成卡片。
- **最近改过的排最前。** 每条记录存最后修改时间（`updatedAt`，卡片上显示为 `2026-11-25 17:40`），两个界面都按修改时间倒序。
- **每张卡片都有自动生成的待办 ID。** 徽标是存储 UUID 的前 8 位十六进制，稳定、不需要计数器也不会重号，且由 id 推导，所以更早写入的记录也照样有；旁边的小按钮复制完整 id。
- **每张卡片两个按钮。**「执行待办」把卡片作为一条普通用户消息发进会话，要求智能体去做；「解释待办」发同一张卡片，但要它先解释，并且不要改动。两条消息都带着 id、工作区、状态、修改时间、标题、摘要和详情。
- **三个入口、一份数据。** 左侧栏入口打开整页；右侧边栏标签页只显示当前会话所属工作区；也可以直接手改磁盘上的 JSON。

## 安装

要求：支持 bundle 的 DeepSeek Harness。本文档对应 Desktop 应用（DSH `0.2.2-rc.5`，profile 为 `desktop`）。

克隆仓库后，把这个目录作为 bundle 安装：

- **在应用里**：**插件** → **添加插件** → 选择该目录；或
- **在会话里**：让智能体安装这个本地目录（`plugin_manager` 的 `install_bundle`，参数为目录绝对路径）。

激活后：

- **插件**页会列出 *跨工作区待办本*，带自己的图标；
- 左侧栏多出待办清单入口；
- 右侧边栏的“+”里能在指引页看到它；
- 每个会话的智能体都能调用 `workspace_todos`。

无需构建、无依赖：`client.js` 直接以 Web 模块加载器要求的形态编写，`index.js` 只 import `node:` 内置模块。

## 使用

**左侧栏 → 跨工作区待办本**：中间列显示完整清单，按工作区分组，卡片上显示状态、标题、摘要和元信息。点卡片打开详情弹窗：Markdown 详情、状态、工作区、修改与创建时间，以及 id 的复制按钮。“返回对话”回到会话。

**右侧边栏 → + → 跨工作区待办本**：面板只显示当前会话所属工作区的卡片，用的是同一个详情弹窗。右栏状态按会话保存，切换到别的会话会显示那个会话的工作区。

两个界面都每几秒重读一次清单，智能体改完无需刷新即可看到。

## 智能体工具

| action | 参数 | 作用 |
|---|---|---|
| `list` | `workspace`（可选：路径、路径片段或工作区名） | 返回全部或匹配的卡片，按修改时间倒序 |
| `add` | `title`、`workspace`（绝对目录）、`summary` 与 `details`（可选）、`label`（可选，默认取目录名） | 追加一条未完成卡片 |
| `update` | `id`，以及 `title`、`summary`、`details`、`done`、`workspace`、`label` 中的任意项 | 修改该卡片；`summary`/`details` 传空串表示清空 |
| `remove` | `id` | 删除该卡片 |

每个操作都返回完整清单（含标题、摘要和 Markdown 详情），按修改时间倒序。`id` 来自上一次结果。

## 数据存放

清单是一个文件：

```
<DSH_HOME>/workspace-todos.json
```

```json
{
  "version": 1,
  "items": [
    {
      "id": "…uuid…",
      "workspacePath": "D:\\work\\alpha",
      "workspaceLabel": "alpha",
      "title": "写接口文档",
      "summary": "先补上鉴权和错误码两节",
      "details": "## 范围\n\n- 登录\n- 刷新 token",
      "done": false,
      "createdAt": "2026-11-25T08:00:00.000Z",
      "updatedAt": "2026-11-25T09:40:00.000Z"
    }
  ]
}
```

- 文件不存在即空清单，首次写入时创建；不是本格式或版本不符时报错，不会静默替换。
- 写入先写临时文件再一次 `rename`，操作串行化，两个写入方不会把读写交错。
- 每次操作都先重读文件，所以手工编辑会在下一次页面轮询和下一次工具调用时生效。
- 拆分之前写入的记录只有一段 `text`：读时当作 `details`，标题取第一行非空文本，摘要为空；下次写入时落成三段并去掉 `text`。
- 每次改动都会重写 `updatedAt`。1.0.0 写下的记录只有 `createdAt`，在下次写入前用它代替修改时间。
- 文件里保持记录添加的先后顺序；`list` 和两个界面都按 `updatedAt` 排序，不信任文件顺序。
- `#` 徽标由 `id` 推导，不落盘。
- 页面通过 Connection 共享通道上的精确 Fetch 路由 `/api/workspace-todos` 访问 Host，在浏览器鉴权之后。

## 支持的 Markdown

只有 `details` 字段是 Markdown。支持：段落与换行、`#`–`######` 标题、`-`/`*`/`+` 与 `1.` 列表、`>` 引用、围栏代码、行内代码、粗体、斜体、删除线，以及 `http(s):`、`mailto:` 链接。其余（表格、图片、嵌套列表、引用式链接、任务列表勾选框、HTML、转义）按纯文本显示。

## 限制

- 人不能在页面上新增、编辑、勾选或删除——这是这一版的取向。要让智能体改，或者直接编辑 JSON 文件。
- 一份文件即一份清单：共用同一个 `DSH_HOME` 的两个 DSH 进程写同一文件，没有跨进程锁（按操作后者覆盖）。
- 界面是 3 秒轮询而非推送，智能体改动最多滞后这个间隔。
- “已完成”区域每次进入界面都是折叠的，展开状态不跨访问保存。
- 整页发送的目标是“最近一次显示在屏幕上的会话”；启动后一个会话都没开过时两个按钮都是禁用的，右侧边栏面板则总有它自己的会话。
- 发送出去的是一条普通用户消息：「执行待办」在会话空闲时直接起一轮，除了删掉这条消息没有撤销；「解释待办」要求智能体保持卡片未完成。
- 工作区被删除后，分组保留添加时的名字，排在现存工作区之后。
- 基于 DSH `0.2.2-rc.5` 的 bundle 接口编写，其他版本可能需要小幅调整。


## 验证情况

2.0.0 做过：两个入口的 `node --check`；Host 半在临时 `DSH_HOME` 上的测试——按三段字段新增、修改与清空摘要/详情、落盘结构、修改时间倒序、只有 `text` 的旧记录读成详情并派生标题且下次写入落成三段、版本不符与损坏记录被拒、工作区筛选、删除、Fetch 信封；浏览器半的加载与注册冒烟；中英字典各 38 个键对齐。

1.4.0 及更早：旧记录结构的 Host 测试、浏览器半注册冒烟、Markdown 解析用例、最小 React 替身渲染、以及 1.0.0 在 Desktop 应用里的真机验证。

**未验证**：卡片布局、ID 徽标、复制按钮、两个发送按钮和详情弹窗都没有在运行中的应用里看过——本机拿不到浏览器控制。发送链路走的是输入框同一条 `Session.prompt` 调用和“最近在屏会话”来源，但真实发送还没有实际点过；弹窗的拖拽缩放手柄和最大化状态也还没实际观察。
